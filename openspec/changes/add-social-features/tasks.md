## 9. UX redesign: checkbox registration, shared room/day-plan text, display names

Real usage after section 7 surfaced concrete problems: no way to edit/delete an existing room assignment, a `<select>` listing every week from 2005-2075 for picking which week to manage, and a free-text attendees field nobody needed. This section replaced all three; specs for `identity`, `beach-week-registration`, and `room-assignment` were updated to match (see those files' current content, not history).

- [x] 9.1 Drop `registrations.attendees` (registration becomes a pure checkbox); drop `room_assignments.person`/`label` (and the validation hook that paired them) in favor of one shared `content` text field per (week, room) with a unique index — recreated both collections via migration rather than altering fields in place (no real production data existed yet, confirmed with the user before doing this); verified locally on a fresh data dir and via a full API test (check-in, shared-room-edit-by-a-different-registered-person, unique-index rejection, unregister-revokes-access)
- [x] 9.2 Add self-service display name: `users.listRule`/`viewRule` widened from PocketBase's default (`id = @request.auth.id`) to any signed-in person, so names are visible beyond your own record; verified via API that a second registered person can see the first's name
- [x] 9.3 Replace the week `<select>` with per-card "I'm going" checkboxes on the existing `Timeline`/`BeachWeekCard`, wired through one shared `useMyRegistrations()` fetch at the app root (not one query per card); checking a box opens a single shared panel (check-in list, Rooms, Day Plans) above the calendar, a "Manage" link reopens it without re-toggling, and unchecking closes it and revokes access — verified `BeachWeekCard`'s new props are fully optional and additive (re-diffed against `main`, see 7.2)
- [x] 9.4 Rebuild `RoomAssignments`/`Notes` as card lists (one room / one day per card) with explicit Add/Edit/Save controls against the new shared-text shape, replacing the old radio-button person/label form and the single-date dropdown
- [x] 9.5 Full local Playwright pass against the redesigned UI: no `<select>` anywhere, sign-in, check in via a card checkbox, panel opens, set a display name (reflected in the header immediately — required manually pushing the update into `pb.authStore`, since `.update()` doesn't refresh it), add then edit a room's shared text, add a day plan, uncheck to close the panel and lose access — zero console errors throughout
